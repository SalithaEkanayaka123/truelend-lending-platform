## User Story
As a user, I want Health, migrations, and architecture guards so that the milestone advances.

## Business Value
Establishes the structural invariants the rest of the build is judged against: an unauthenticated readiness probe, tamper-evident migrations and policy files, a one-way layer order, and zero floating-point money.

## Description
Health, migrations, and architecture guards

## Scope
**In:** GET /health (public, under 1000ms once ready); numbered SQL migrations applied once and recorded with a SHA-256 in schema_migrations; startup abort on a changed applied migration (MIGRATION_CHECKSUM_MISMATCH); an automated layering test (types < config < repository < service < api < ui, one-way); a static scan for float types/calls and REAL money columns; seeding users (F0) and policy version 1 as APPROVED
**Out:** any functional endpoint beyond health

## Acceptance Criteria
- **E1-S4-AC1** — *Given* the process has reported ready, *when* GET /health is requested without a token, *then* it is 200 {"status":"ok"} in at most 1000 ms.
- **E1-S4-AC2** — *Given* migrations 0001 through 0003 already applied, *when* the app starts again, *then* none re-run and schema_migrations still has 3 rows with SHA-256 values.
- **E1-S4-AC3** — *Given* applied migration 0002 edited on disk, *when* the app starts, *then* startup aborts with MIGRATION_CHECKSUM_MISMATCH and /health never returns 200.
- **E1-S4-AC4** — *Given* the source tree under backend/src/truelend and frontend/src, *when* the layer test runs, *then* no module imports from a higher layer in the order types, config, repository, service, api, ui.
- **E1-S4-AC5** — *Given* the money code paths, *when* the static scan runs, *then* it finds no float type, no float( call, and no REAL money column.
