## User Story
As a user, I want Manual review and override so that the milestone advances.

## Business Value
A human underwriter (or, for an override, an admin) must be able to resolve a MANUAL_REVIEW or reverse an AUTO_REJECT, with every such action audited.

## Description
Manual review and override

## Scope
**In:** POST .../review with outcome APPROVE|REJECT and a 1-500 character reason, UNDERWRITER only; POST .../override with reason_code (from the policy's override_reason_codes) and a comment, UNDERWRITER or ADMIN, on an AUTO_REJECT with no resolution yet; audit rows REVIEW_APPROVED, REVIEW_REJECTED, DECISION_OVERRIDDEN with before/after status
**Out:** overriding anything other than an AUTO_REJECT; listing/filtering applications across the portfolio (FR-10, deferred to M2)

## Acceptance Criteria
- **E3-S5-AC1** — *Given* application 2 in MANUAL_REVIEW, *when* UNDERWRITER user 3 POSTs {outcome:"APPROVE", reason:"Stable income, documents verified"}, *then* it is 200, status APPROVED, resolution MANUAL_REVIEW/APPROVED, an audit row REVIEW_APPROVED with actor 3, and an ApplicationApproved event.
- **E3-S5-AC2** — *Given* the same state, *when* they POST REJECT with a reason, *then* status REJECTED, audit row REVIEW_REJECTED, and no event.
- **E3-S5-AC3** — *Given* application 3 with decision AUTO_REJECT, *when* ADMIN user 1 POSTs {reason_code:"COMPENSATING_FACTORS", comment:"Co-signed by parent; income verified"}, *then* it is 200, status APPROVED, the decision row still reads AUTO_REJECT, an audit row DECISION_OVERRIDDEN with actor 1, the reason code, the comment, before REJECTED/after APPROVED, and an event.
- **E3-S5-AC4** — *Given* application 4 with AUTO_REJECT, *when* UNDERWRITER user 3 overrides with DATA_CORRECTION, *then* the same outcome as AC3 with actor 3 in the audit row.
- **E3-S5-AC5** — *Given* an application in MANUAL_REVIEW or already overridden, or a reason_code "FOO" or an empty comment, or review on an application not in MANUAL_REVIEW, or a CUSTOMER token, *when* override or review is called, *then* it is 409 NOT_OVERRIDABLE, 422, 409 NOT_IN_REVIEW, and 403 respectively.
