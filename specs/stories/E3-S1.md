## User Story
As a user, I want Verification queue so that the milestone advances.

## Business Value
An underwriter must be able to see all pending documents in one queue and clear each one, VERIFIED or REJECTED, with an audited reason.

## Description
Verification queue

## Scope
**In:** GET /api/verification-queue listing UPLOADED documents oldest first, paginated; POST /api/documents/{id}/verify with outcome and a 1-500 character reason; VERIFIED is final; only a REJECTED document can be replaced
**Out:** document content review (metadata only)

## Acceptance Criteria
- **E3-S1-AC1** — *Given* submitted application 1 with 3 UPLOADED documents, *when* UNDERWRITER user 3 GETs /api/verification-queue, *then* 3 items return oldest first, each with document_id, application_id 1, and type.
- **E3-S1-AC2** — *Given* document 1, *when* user 3 POSTs {outcome:"VERIFIED", reason:"Name matches PAN record"}, *then* it is 200 VERIFIED, verified_by 3, an audit row DOCUMENT_VERIFIED is written, and the item leaves the queue.
- **E3-S1-AC3** — *Given* document 2, *when* user 3 POSTs {outcome:"REJECTED", reason:"Image unreadable"}, *then* it is 200 REJECTED with the reason, an audit row DOCUMENT_REJECTED is written, and the application still reads SUBMITTED.
- **E3-S1-AC4** — *Given* a missing, empty, or 501-character reason, *when* posted, *then* it is 422 VALIDATION_ERROR and no audit row is written.
- **E3-S1-AC5** — *Given* a CUSTOMER token, or an already VERIFIED document, *when* they GET the queue or POST verify, or verify is posted again, *then* it is 403 for the CUSTOMER token and 409 ALREADY_VERIFIED for the already-verified document.
