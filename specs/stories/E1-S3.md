## User Story
As a user, I want JSON logs, correlation IDs, and redaction so that the milestone advances.

## Business Value
Synthetic PII (PAN, Aadhaar) and document filenames must never leak into logs, and every request must be traceable end to end by a correlation ID.

## Description
JSON logs, correlation IDs, and redaction

## Scope
**In:** one structured JSON log line per request with ts/level/event/correlation_id/method/path/status/duration_ms; inbound X-Correlation-ID reuse/validation, generated UUID4 fallback, echoed response header; a redaction filter masking PAN/Aadhaar patterns and document filenames anywhere in a log record; the 500 error envelope with no stack trace in the response
**Out:** request/response body logging of any kind

## Acceptance Criteria
- **E1-S3-AC1** — *Given* any completed request, *when* output is captured, *then* exactly one JSON log line has the keys ts, level, event, correlation_id, method, path, status, duration_ms.
- **E1-S3-AC2** — *Given* no inbound X-Correlation-ID, or an inbound `req-12345678`, or an inbound `a b!`, *when* the request completes, *then* a missing header yields a UUID4 echoed in the response header and equal to the log's correlation_id, `req-12345678` is reused as-is, and `a b!` is replaced by a UUID4.
- **E1-S3-AC3** — *Given* an application created with PAN ABCDE1234F and Aadhaar 1234 5678 9012, *when* all captured logs, including error paths, are scanned, *then* neither ABCDE1234F, 123456789012, nor 1234 5678 9012 appears.
- **E1-S3-AC4** — *Given* a document upload with filename salary_slip_jan.pdf, *when* logs are scanned, *then* the document ID appears and the filename does not.
- **E1-S3-AC5** — *Given* an unhandled exception, *when* it propagates, *then* the response is 500 with the error envelope and no stack trace, and the trace is logged as JSON through the redaction filter.
