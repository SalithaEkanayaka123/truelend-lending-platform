## User Story
As a user, I want Apply for a loan so that the milestone advances.

## Business Value
The customer's first concrete action: creating a DRAFT application pinned to a product and generating the right document checklist for it.

## Description
Apply for a loan

## Scope
**In:** POST /api/applications creating a DRAFT with a per-product required-documents checklist (MISSING); amount/tenure range validation against the active policy; PAN/Aadhaar format validation and masked display (pan_masked, aadhaar_masked); ownership: another customer's application returns 404
**Out:** co-applicants; editing an application after submission; withdrawing an application

## Acceptance Criteria
- **E2-S2-AC1** — *Given* customer user 4 and policy v1, *when* they POST /api/applications with PERSONAL, amount "200000.00", tenure 24, age 30, income "60000.00", no flags, PAN ABCDE1234F, Aadhaar 123456789012, *then* it is 201 with id 1, status DRAFT, applicant_user_id 4.
- **E2-S2-AC2** — *Given* that application, *when* it is returned, *then* required_documents is ID_PROOF, ADDRESS_PROOF, SALARY_SLIP (each MISSING); a VEHICLE application lists 4 documents including VEHICLE_QUOTATION; an EDUCATION one includes ADMISSION_LETTER and FEE_STRUCTURE.
- **E2-S2-AC3** — *Given* PERSONAL, *when* tenure is 72 (max 60), or amount is "10000.00" (min 50000.00), *then* it is 422 TENURE_OUT_OF_RANGE or 422 AMOUNT_OUT_OF_RANGE respectively.
- **E2-S2-AC4** — *Given* PAN "abc" or an 11-digit Aadhaar, *when* posted, *then* it is 422 VALIDATION_ERROR; a valid application returns pan_masked "******234F" and aadhaar_masked "********9012" and no raw values.
- **E2-S2-AC5** — *Given* customer user 5, *when* they GET /api/applications/1, *then* it is 404.
