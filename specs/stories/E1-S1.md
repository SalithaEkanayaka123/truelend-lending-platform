## User Story
As a user, I want Authentication and role guard so that the milestone advances.

## Business Value
Every other capability in the platform sits behind this guard; without it no role (customer, underwriter, policy editor, admin) can be told apart or kept out of data that is not theirs.

## Description
Authentication and role guard

## Scope
**In:** POST /api/auth/login issuing a 1800s bearer JWT (HS256) keyed by email/password; GET /api/auth/me; a router-level auth dependency applied to every route except login and health; role enumeration CUSTOMER, UNDERWRITER, POLICY_EDITOR, ADMIN
**Out:** token refresh; password reset; user administration (seed users only)

## Acceptance Criteria
- **E1-S1-AC1** — *Given* seeded user customer1@example.test with the correct password, *when* they POST /api/auth/login, *then* the response is 200 with expires_in 1800 and role CUSTOMER.
- **E1-S1-AC2** — *Given* a wrong password, *when* they POST /api/auth/login, *then* it is 401 UNAUTHENTICATED with no token and the same body whether or not the email exists.
- **E1-S1-AC3** — *Given* no Authorization header, or a token 1801 seconds old, *when* they GET /api/auth/me, *then* it is 401.
- **E1-S1-AC4** — *Given* a CUSTOMER token, *when* they GET /api/audit, *then* it is 403 FORBIDDEN.
- **E1-S1-AC5** — *Given* the registered route table, *when* it is enumerated, *then* every route except POST /api/auth/login and GET /health declares the auth dependency.
